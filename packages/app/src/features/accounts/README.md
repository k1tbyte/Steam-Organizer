# accounts

The vault's account list: search, ban filters, sort, pinned and all groups as a virtual grid of cards, edit mode, the Card fields panel, and the Add account overlay.

- `index.ts` exports `accountsRoutes`, the model types, `useVaultAccounts` (the vault's accounts, the one source other screens read and the one writer of pins, order, new accounts, the user's fields (`edit`: alias, note) and deletions (`remove`: tombstones, resolving to an undo that puts the same sealed records back, newer, unless the login came back meanwhile)), `useRemoveAccounts` with `RemoveAccountsDialog` (delete with Undo), `steamNameOf`, `useAccountPassword` (the Steam password a copy or a fill takes) and the card parts other screens reuse: `AccountCard`, `LevelAvatar` (level ring, sizes from a list row's `xs` up to the profile's `xl`), `AgeChip`, `AccountTagChip`, `BanLetters`, and `BAN_KINDS`.
- `model.ts` holds `Account`, the one shape the list, the card and the profile read. Its `nickname` is the alias, else the Steam nickname, else the login; the card and the profile show the Steam nickname small and grey beside an alias (`steamNameOf`), and the nickname search finds both.
- The list is virtual by rows (`useAccountRows`, TanStack Virtual against `useScrollRoot()`): columns follow the measured width (`auto-fill`, 340px minimum), row heights come from `services/cardLayout.ts`, which mirrors the card's CSS and also feeds the "Card height" readout. A card is never measured. Rows key by slot (`services/listSlots.ts`) and cards by column, so a row that scrolls in reuses the nodes of one that left; card state tied to one account (a copy mark, a held Guard code) resets when the account changes.
- The list has one context menu (`FpContextMenu` in `AccountsGrid`, `useAccountMenu`): a right-click on a card, or the touch card's More button, opens it for the card's `data-account-id`. It keeps the id, not the node (a recycled node shows another account), closes when that account leaves the vault, the list scrolls or its card node goes to another account (a resize), and hands focus back only to a control still in that account's card. Copies toast; locked accounts copy nothing. Edit tags is the grid's intent, unwired upstream.
- Delete (`useRemoveAccounts`): the card's trash removes at once; the context menu, the edit bar's batch and the profile menu ask first (`RemoveAccountsDialog`: one account with its Steam side, a batch by its first four names and a count). Either way a toast offers Undo for 8 s (hover pauses it) and says when the accounts are back. A lock drops every toast (`useLockClearsToasts` in `features/shell`), so an Undo never outlives its vault.
- Accounts are `ACCOUNT` records of the open vault (`services/vaultAccounts.ts` maps them to `Account` in the fractional `order`, tags from `TAG` records). Pins, moves and Add go through `useVaultSession().transact`; a move stores its intent (the moved ids between two neighbours), so cards a filter hides keep their places. `stores/accountsView.ts` shows pins and order until every write settles, so a moved card never snaps back; a sample keeps them for the session.
- Search field, ban filters (any, require, exclude), sort and the Card fields flags persist through `core/storage` (`stores/accountsView.ts`, `stores/cardFields.ts`).
- Edit mode is `?edit` (`composables/edit/`): the list shows what the search and ban filters let through in the vault order (the sort waits, the stored one untouched) in `AccountsEditGrid`; a moved card lands right after its shown neighbour (before it at the group's start), and cards the filter hides stay where they were. `EditBar` keeps the ban chips and swaps the sort and tools for the status, Clear and Done (outside the chips' scroll on phones). The grid places cards at `translate` offsets and keeps a card's node while it is on screen, so a move slides it; a card that comes in takes the node of one that left, like `AccountsGrid`. A cover over each card takes its presses: a mouse drags a card from anywhere, touch from the grip that replaces its pin (`AccountCard` `hidePin`); arrows move the focused card. Cards go `inert` only while the keyboard is in the grid: inert content (or `pointer-events: none`) costs Chrome a compositor layer per card part. The slot follows the pointer: neighbours make room once it rests over a card, never while the list scrolls, and off the group's cards the card goes back to its place. A move commits to the order once it has landed: committing reorders the DOM, which would cut its transition. Cards move within their group only. A click, tap or Space picks a card, Shift the range from the last one, Ctrl/Cmd+A or the bar's Select all every shown one, a mouse rectangle from the page's empty space every card it touches on top of the picks it started from (`useMarquee`; hits are arithmetic over the group geometry, so cards scrolled out count; Esc puts the picks back), in both groups (`useEditSelection`, module state the bar and the grid share; a pick a filter hides drops; Esc clears the selection before leaving the mode). Dragging a picked card carries its group's picks as a stack that takes one slot: picked cards on screen fly into it, and on the drop they fan out together at its slot in their order. A stack of the whole group, or all of it but one card, would move nothing, so the held card goes alone. The bar's menu acts on the picks: Pin, Unpin and Delete are wired, the rest are intents.
- Add account is `?add-account` (`useQueryOverlay`, `composables/add/`): a modal on desktop, a sheet on phones. Name is the alias: required without a Steam ID the text gives (a vanity name, a friend code or a custom URL counts as none until the lookup), flagged only after Add was tried (the button greys out until it is filled). Web cannot reach Steam: it leads with Name, always required, and shows where the Steam profile is added instead of the field. `detectSteamId` (`core/steamId.ts`, shared with the profile's ID formats) recognizes the eight identifier formats; `parseAccountId` reads the account ID from every one but a vanity name, a friend code or a custom URL. Until the Steam lookup is wired, Add saves what the text gives and no profile data: a vanity name, a friend code or a custom URL lands without a Steam ID (the lookup will resolve them and block an ID Steam does not find; `features.md` 4). Add rechecks the login (by `loginTag`) and the Steam ID in the write queue.
- The card's title links to `/accounts/:id` (`features/profile`). The card whose id is `useRouteHero()` carries `data-vt-hero`, the shared element of the card to profile morph (`features/shell`).
- Steam Guard code, countdown and hold-to-reveal come from `features/steam-guard`.
