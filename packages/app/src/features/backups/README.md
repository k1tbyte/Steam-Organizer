# backups

The open vault's Drive backups (`@so/core` `drive/backups.ts`), the restore dialog and the state without Drive. Also owns Drive sync: the engine, its settings, the auto backup and `SyncStatus`, the indicator pages put in the topbar.

- `stores/useVaultSync.ts` is the engine, for the open vault while it is linked (`useVaultSession().vault.sync`) and Drive is connected. `sync()` runs one at a time (a call meanwhile runs it once more after): it lists the vault's copies (`@so/core` `drive/vaultCopy.ts`); when the kept copy (the oldest) is the one merged last and nothing is pending it only marks the vault synced, when only this device changed it pushes without a download, otherwise it reads each copy into `mergeCopy` (extras first, the kept one last), pushes when the copy lacks something, marks the receipt with the copy's new version and deletes the extras. A result for another vault or Google account never lands (`useBackupList().scope`). A copy gone with a copy id held, or another Google account than the link's, is the copy-gone rule: `unlink()` and a notice, nothing recreated. A failure is held for its vault and account; the first of a streak notices (Sync now starts a new streak), a copy that can't be read is reported and never written over. `flush` pushes the file a lock left (`onLocked`), without the key, only over the copy it was merged with. `backUpIfDue()` saves an auto backup when `services/autoBackup.ts` says so (none in a day, a record changed after the newest) and keeps the newest ten autos; manual ones stay.
- Sync settings (Auto sync, its interval, Auto backup) belong to the engine, per device under `SYNC_SETTINGS_STORAGE_KEY`; Settings and the side block bind the same values.
- `useAutoSync()` (the shell calls it once, so it lives with the unlocked session) syncs with Auto sync on: when the shell mounts or another vault opens, on focus and on becoming visible, every interval, 3 s after a write that left the vault pending, and when Drive turns connected. It checks the auto backup 30 s after the last change, hands `flush` every lock, and turns notices into toasts ("{name} is no longer in Google Drive", "Drive sync failed" with Retry).
- `useSyncStatus()` is the open vault's state for the status line, undefined for a vault on this device only: offline, error (expired or disconnected Google, or a failed run: `cause`), syncing, else synced with its age ("just now", then `formatAgo`, moving on one shared minute clock).

- Desktop: history card beside a side block (Google identity, vault line, Auto backup / Auto sync, "More in Settings"). Phone: compact rows with icon buttons.
- Restore is `useQueryOverlay('restore')` with the backup id as its value, so a deep link `?restore=<id>` opens it. An unknown id closes it.
- The list lives in `stores/useBackupList.ts`, held with the vault and Google account it was read for, so another one never sees it; `useBackupCount()` (the facade) gives Settings its length and lists once when nothing is held.
- The history lists this vault's backups through `useDrive().run`, again on each visit (the page is resident) and when the vault or the Google account changes; an answer, a save or a pending row for another one never lands, and a failed refresh replaces the rows with its error and Retry. Backup now saves `useVaultSession().snapshot()` with a pending row on top, and gives up if the vault or account changed while the write queue drained; it is blocked while saving, without a connected Drive, in error or offline. Delete is optimistic: a failure puts the row back, a backup already gone counts as deleted. Failures read through `useDriveProblem()`.
- Restore asks no password: the session's key opens this vault's backups. It reads the backup with that key and hands its records to `useVaultSession().replaceRecords`: stamped now, tombstones for what the backup lacks, in one write.
- A vault kept on this device (no link) shows "No backups for this vault" even with Google connected: backups and sync come together. Move to Google Drive (`useMoveToDrive`) connects from the click when needed, links the vault and syncs at once, so a copy Drive already has of it is merged, not duplicated; Export file opens Settings → Vault. A synced vault while Google is signed out shows "Google Drive isn't connected" with Connect Google Drive.
- The Google account and its state come from `useDrive()` (`#features/drive`): an expired sign-in shows as the error state with Sign in again, a failed sync with Retry, no network as offline. Disconnect revokes the token.
- "More in Settings" opens the Sync & backup section through `useSettingsLink()` from `#core` (settings imports features, so backups never imports it).
